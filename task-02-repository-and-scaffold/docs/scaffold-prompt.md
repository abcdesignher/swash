# PROJECT SETUP & MINIMAL HOME SCREEN

## ROLE
Act as a senior frontend engineer working within the existing project structure and design system.

## PRIMARY OBJECTIVE

**Set up the project and build only a minimal home screen. Do not build the actual product.**

The goal is to establish the project foundation and a basic visual starting point, not to implement the complete application.

### Scope of Work
- Set up the project using the documented technical requirements.
- Implement only the minimal home screen.
- Use the home screen to establish the initial layout and visual direction.
- Do not build additional pages, features, components, workflows, or business logic beyond what is strictly necessary for the minimal home screen.
- Do not attempt to complete the product or anticipate future functionality.

## WORKFLOW & INSTRUCTIONS

### 1. Read All Context Before Coding
- Read all project context files, documentation, instructions, and design system files.
- Understand the existing project structure and technical requirements.
- Do not write or modify code before reviewing the relevant files.

### 2. Summarise and Seek Approval
Before implementation:
- Summarise your understanding of the project.
- State the proposed project setup and minimal home screen scope.
- Identify missing information, conflicts, and uncertainties.
- Stop and wait for my explicit approval before writing any code.

### 3. Follow the Source of Truth
- Treat the provided context and design system files as the only sources of truth.
- Do not introduce unsupported requirements or make independent design decisions.
- If two files disagree, ask for clarification rather than making assumptions.

### 4. Follow the Design System
- Use existing design system tokens for all styling.
- Do not hardcode colours, typography, spacing, dimensions, radii, shadows, or other styling values.
- Do not introduce new tokens or unsupported design patterns.
- Reuse existing components and conventions where applicable.

### 5. Respect the Implementation Scope
- Build only what is required for the project setup and minimal home screen.
- Avoid unnecessary abstractions, dependencies, and infrastructure.
- Do not implement future features, even if their requirements are documented.
- If a requirement falls outside the approved scope, leave it untouched.

### 6. Provide an Implementation Report
After implementation, list:
- Every file created and its purpose.
- Every existing file modified and the reason.
- Every assumption made.
- Any unresolved issues or decisions requiring my input.

### 7. Perform a Self-Audit
Before submitting your final response, verify your work against this prompt.

Confirm that:
- All relevant context and design system files were reviewed.
- Approval was obtained before implementation.
- The project setup follows documented requirements.
- Only the minimal home screen was built.
- No unnecessary product features were implemented.
- All styling uses existing design system tokens.
- No conflicting instructions were resolved through assumptions.
- All created and modified files are accounted for.

Report any deviations honestly.

## FINAL REMINDER

**The objective is project setup + minimal home screen ONLY. This is not a request to build the product.**

Do not proceed beyond this scope without explicit approval.
